# 用户级与 Agent 级能力管理方案

> 状态：2026-09-22 已完成第一阶段。按产品讨论收窄范围：本轮只处理用户级与 Agent 级。项目级留给未来的项目 Tangu 详情界面；现有项目技能扫描及 `.tangu` / `.forsion` 路径行为未改动。下文记录设计依据，实际交付边界见末尾「实施记录」。

## 确定的入口

| 位置 | 负责什么 | 不承担什么 |
| --- | --- | --- |
| **设置 → 全局技能** | 用户级技能的查看、创建、导入、编辑、停用、删除及云端可用性；随包技能的阅读与复制 | 不在这里逐个配置 Agent 的启用名单 |
| **Agent Space → Agent → 能力** | 该 Agent 的专属技能、继承的全局技能、工具权限与 MCP 可用性 | 不直接改动全局技能原件 |
| **Tangu 详情 → Agent → 能力** | 当前 Agent 的同一份能力配置；窄栏呈现 | 不维护第二份状态或一套语义不同的开关 |
| **设置 → 智能体** | 用户画像、默认 Agent 与后台/外部 CLI 等全局入口 | 不再保留普通 Agent 的第二套 CRUD 长表单 |

Agent Space 的 `AgentProfile` 已在 Tangu 详情里以 `compact` 形式复用。两处继续共享组件、保存服务与状态刷新；窄栏只改变排版，不改变数据或动作含义。普通 Agent 的新建、复制、排序、设默认和删除归 Agent Space 名册。设置中的旧入口跳到对应 Agent。

## 设置里的“全局技能”怎么做

“全局”说明**存放及可见范围**：它可供所有适用的 Agent 发现，不代表每个 Agent 每轮都要加载或执行。每个 Agent 仍可决定是否使用。页面应比现有的来源分组长清单更像一个可管理的资料库：

```text
设置 / 全局技能
为所有 Agent 准备做事说明书；各 Agent 可以单独调整是否使用。

[搜索名称或用途                         ] [来源 ▾]  [+ 添加技能]

本机技能  22                        [打开此设备目录]
  我的技能  8
  写作规范         一句话用途              自建 · 本机        ···
  发布网站         一句话用途              已导入 · 本机      ···

  随包提供  14  ▸  （默认折叠；搜索命中时展开）

我的云端副本  2                     （与本机技能分开展示）

选中“写作规范” → 右侧详情 / 窄窗整页：
  名称、用途、来源、当前可用状态
  SKILL.md 阅读预览  |  文件清单  |  实际路径
  [编辑] [复制给 Agent…] [更多 ▾]
```

界面只保留一个主要动作 **“添加技能”**，菜单包含“新建技能”“导入文件夹/文件”“从 Agent CLI 导入”“浏览市场”。创建和导入前显示将写入的实际全局目录，并预览技能名称、说明与随附文件；导入默认复制，不改原件。同名时先比较内容，明确选择保留原件、另取名称或替换，绝不静默覆盖。

列表一行显示名称、一句用途、来源与状态，不铺开整篇描述。来源是次级徽标和筛选：内置、插件、市场、手写、Agent 自建、Claude/Codex 导入等都不应被误认为作用范围。真实目录从后端获取，界面不硬写 `~/.tangu/skills`；桌面当前的实际用户目录通常在 `~/.forsion/tangu/skills`。当前列表可能读外部后端，但“打开目录”始终打开此设备目录，两者不一定相同；外部模式须清楚标出位置并禁用不适用的本机写入动作。技能详情的正文与附属文件需要独立读取接口，现有列表描述不能冒充完整预览。

**我的技能**可以编辑、打开目录、复制给 Agent、临时停用、删除；这些动作藏在行末菜单和详情中。停用是可恢复的可用性状态，不靠改名或移动文件实现，且只停用全局这一份；某 Agent 自己持有的同名专属版本仍按其自身规则生效。删除与替换要展示影响的 Agent 和备份/撤销途径。**随包提供**的原件只读，可以预览、查看来源、复制为可编辑的全局或 Agent 版本。当前 `source=local` 混合多种归属，不能作为可编辑/可删除判据；后端需返回真实所有权与只读状态。

**我的云端副本**单独成组，因为当前“上传技能”只发布名称、描述与正文等元数据，不上传 `scripts/`、`references/` 等目录资源，也不与本机原件保持同步；重复上传还会创建另一份云端条目。操作文案应写“发布正文副本”，成功后展示云端副本而非“已同步”。含辅助文件的技能应在发布前提醒其云端执行可能缺文件；未来若支持整目录与覆盖更新，再改称“同步”。

## Agent Space 与 Tangu 详情怎么显示全局技能

Agent 的“能力”页内切 **技能 / 工具 / MCP**。技能列表分为两组：

1. **此 Agent 专属**：位于 `agents/<slug>/skills`，在这里创建、导入、编辑和删除。创建入口已带当前 Agent，无须再选层级。
2. **继承自全局**：展示全局技能的名称、用途与该 Agent 的使用状态。这里的开关仅修改该 Agent 的可用策略；点击详情可以阅读，编辑原件则通过“在设置中编辑”深链进入全局技能并在返回后保留当前 Agent。

当专属技能与全局技能同 id 时，两份都能在详情中找到；专属版标为“当前生效”，全局版标为“被此 Agent 的版本覆盖”。用户可以复制全局技能为该 Agent 的专属版，再修改它，不会改变其他 Agent。技能状态至少解释“可用”“该 Agent 已停用”“被专属版覆盖”“当前会话模式不加载”，避免只给一个缺乏原因的复选框。

默认策略显示为 **自动使用适用技能 / 自选技能 / 全部关闭**。自动模式会纳入后来新增的用户级与该 Agent 专属技能；自选模式兼容现有 `enabledSkillIds` 白名单，新增技能需手动启用。旧 Agent 的保存值不静默转换，用户主动切换策略时才改语义。Agent Space 和 Tangu 详情使用同一策略组件与同一保存逻辑；切换 Agent 前保留或处理未保存草稿，不能丢失修改。

## 设置里的“智能体管理”收敛

Agent Space 是普通 Agent 档案的主场：名册顶部直接“新建”，行末菜单集中“设为默认、复制、同步、打开文件夹、删除”；创建后立即进入新档案。设置里不再重复头像、人格、模型、技能白名单等表单，只显示当前默认 Agent、用户画像、后台运行与 Agent CLI 的明确入口。桌面设置处于独立浮窗，旧表单只刷新浮窗 Zustand、主窗可能仍显示旧名册；迁移后所有突变都要通知主窗刷新。

Tangu 详情允许编辑当前 Agent 的技能与其他能力，因为它复用相同的 `AgentProfile`。复杂的新建/导入表单可以在窄栏打开同一编辑器的整页/浮层，但作用对象和返回位置必须保留。Muse 需要把“对话默认”和“后台运行”明确分开：两者现在可能读取不同模型与权限配置，界面要在真正生效的字段旁标明用途，后台字段保留一个编辑入口。

右栏始终跟随当前主会话：显示其会话模型覆盖与用量；Agent Space 显示跨会话默认配置。两处的选中标签和搜索可各自保留，但“在 Agents 中打开”应带当前 Agent 与能力分段。两个已打开的 `AgentProfile` 有独立草稿，保存整份旧草稿可能覆盖另一处刚改的字段；写入需按变更字段提交并检查版本冲突。新技能落盘后两处都要收到能力库刷新事件，不能等到重挂页面才看到。

## 数据与实现契约

- 后端增加**带范围的目录结果**：用户级与指定 Agent 的每份技能分别返回 `id/name/description/scope/path/provenance/readOnly/availability/shadowedBy`，而非只把赢家合成一行。当前 `SkillInfo.source` 是渠道，不是范围；`origin: agent` 表示作者，也不是 Agent 级。
- 运行时与 UI 共用同一解析顺序：内置/插件提供 < 用户级 < 当前 Agent 专属。同 id 的胜出关系由后端给出，前端不猜路径。现有项目级扫描继续工作，但不纳入这次的编辑 API 与界面改造。
- 管理写入经同一服务校验 slug、只读来源、同名及目标目录；写入和替换要保护整个技能目录（`SKILL.md` 及辅助文件）。全局暂停/Agent 停用是配置状态，和删除文件分开。
- 设置浮窗、主窗 Agent Space、Tangu 详情订阅同一刷新事件；创建/删除/设默认/启停后，名册、新会话选择器及能力列表即时一致。两个档案视图并发编辑时使用字段级更新与版本检查，不让后保存的旧草稿覆盖先保存的字段。
- 保留旧 `/agent/skills` 给现有消费者，新目录接口分批接入；移除设置旧 Agent CRUD 前先完成跨窗通知与深链。外部导入、云端上传须在 UI 中如实反映其文件覆盖范围。

## 验收

- 全局新建技能后，自动模式的两个 Agent 都能看到；停用一个 Agent 的继承资格，不改变另一 Agent 或全局文件。
- 将全局技能复制给 Agent 并修改后，该 Agent 使用专属版；设置仍能找到全局原件并解释覆盖关系。
- 包内置技能只读；导入同名先展示冲突；含辅助文件的技能发布云端时明确告知只发布正文与元数据。外部后端模式下，本机目录动作不伪装成远端技能目录。
- 两个 Agent 入口对同一项启停、创建与删除即时一致；设置浮窗关闭前后主窗口名册和新会话选择器同步；切换对象不丢草稿。
- 老的 `enabledSkillIds` 保持自选行为，自动模式才包含未来新增技能。项目目录和已有项目会话行为在本轮保持原样。
- 扩展 `check:agentprofile`、`check:settingsui`、`check:parity`，验中英、亮暗、窄栏、键盘、空态与错误态；实际观感按 `DESIGN.md` 看真实截图。若改技能装载或 `agentLoop`，按仓库要求跑真模型 live harness。

## 实施记录（2026-09-22）

- 设置中的全局技能库已接入带范围的本机目录与详情，支持搜索、来源筛选、新建、复制整个技能目录、导入文件夹、编辑正文、停用、删除前确认与删除后备份路径。随包和兼容旧目录名的技能只读；旧目录可用合法新名称复制。云端正文副本单独成组。
- Agent Space 名册承载普通 Agent 的创建、设默认、排序和删除；设置改为总览入口。Agent Space 与 Tangu 详情复用 Agent 技能面板，区分专属与继承技能，支持自动、自选、关闭三种策略，技能操作后向其他窗口广播刷新。
- 新建与导入遇到同名时返回冲突，用户可改目录名重试；当前未提供内容差异预览或原地替换。导入入口复制整个文件夹，但当前不提供导入前的附属文件预览。删除返回备份目录，尚未在确认框中逐一分析受影响的 Agent。
- Agent 名册的复制、同步和打开目录快捷动作，以及更细的市场/CLI 来源标签仍属后续完善。并发编辑采用保存前内容检查与字段级 Agent 更新，尚非服务端原子版本事务。

## 响应式与操作细化（2026-09-22）

- 名册拆成原生 `agents-roster` 左侧视图，与主区 `agent-profile` 分离；支持工作台收起和拖宽，旧布局在缺少名册时补入。主区档案限制阅读宽度，窄容器使用与 Tangu 详情一致的紧凑排列。
- 技能来源、添加、更多操作、Agent 技能策略、名册动作和后台设置选择器共用 `CapabilityMenu`：Portal + `OverlayAt`、菜单字号与动效 token、键盘导航、Escape 焦点恢复及减少动态效果。
- 后台智能体采用 Historian / Muse 选择导航，只展开当前对象；高级提示词、通知、预算默认收起。修改暂存为草稿，切换设置页面仍保留未保存内容，一次保存字段差异，文件夹换行不会在输入时被清理。失败保留输入，放弃修改恢复已保存值。
- 验收入口：`check:agentprofile`、`node scripts/global-skills.check.cjs`、`e2e:musesettings`，覆盖原生侧栏、宽窄界面、菜单键盘、草稿和真实请求接线。布局规范同步至仓根 `DESIGN.md`，适用于 Genesis 全界面。
