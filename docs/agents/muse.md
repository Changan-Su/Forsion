# Muse 主动助理

大多数 AI 等你开口。Muse 反过来:你交代一句"盯着点",它就持续留意,到点、到事、到条件满足时**主动来找你**。

Muse 是一个「后台智能体」,和名册里的其他 Agent 一样有自己的人格、指令和长期记忆,可以像编辑普通 Agent 那样定制它。

## 开启与运行节奏

本版本升级时会把尚未开启的 Muse 与 Historian 一次性打开，并记录迁移状态；升级后手动关闭会被尊重，不会在下次启动时自动打开。Muse 当前在本地模式运行，可在后台智能体设置里配置活跃时段、心跳频率、通知和预算。它由三类条件唤醒：**心跳到期、自己的日程到期、盯任务规则命中**。

每轮会参考近期工作、自己的记忆与日志，以及你对先前建议的处理结果，在设定的权限内准备资料、提出下一步或执行工作。

### 三档权限

| 模式 | 如何处理操作 |
| --- | --- |
| **审批** | 可以在自己的 Library 与 Space 内工作；越界写入、命令等操作进入待批队列，等你决定。 |
| **代批** | 先让默认 Agent 代为判断一次；未获批准的操作仍进入待批队列。 |
| **全开** | 按全自动档执行，将你配置的授权文件夹纳入可写范围。 |

权限、预算与运行时段决定 Muse 能持续推进到哪一步。

## 盯任务

对 Muse 说人话就能布置监视任务:

- "每天早上 9 点给我今天的日程摘要";
- "我下次打开这个项目的时候提醒我改配置";
- "每隔两小时提醒我起来活动"。

Muse 把这些登记成规则，条件命中后唤醒 AI。**规则的等待本身不调用模型**；如果同时开启心跳，心跳周期仍会发起工作并产生模型用量，实际执行受预算约束。

触发方式与[自动化](../spaces/automation.md)共用同一套:定时(每天几点 / 某一个时刻 / 每隔多久)与事件发生时。完整的触发目录在自动化页里,包括插件声明的事件。

> 定时提醒统一由自动化承担。[收件箱](../spaces/inbox.md)只负责收信,不负责定时。

## 结果送到哪

- **通知**:右上角卡片,可在 设置 → 选项 → 通知 里按事件开关;
- **[收件箱](../spaces/inbox.md)**:留底,回头能翻;
- 收件箱里的消息可以**转发到[通道](../chat/channels.md)**——重要提醒直接推到手机上的微信 / Telegram / QQ。

## 建议清单

除了你交代的任务，Muse 也会在运行周期中提出下一步建议。建议进入收件箱并带有任务卡：可以选择**交给 Muse 执行**、**新会话执行**或**忽略**，处理结果同步回待办列表。交给 Muse 执行代表批准该任务开始；超出它权限的具体操作仍需审批。

待批请求同样可以在收件箱中批准或拒绝。在对话里的任务卡上，也可以把后续事项交给 Muse 跟踪。

Muse 会记住你采纳过、忽略过哪些建议,提的东西越来越贴你。

## Muse 自己的工作区

Muse 会把草稿、资料和每日工作日志积累在自己的 **Library**。它也可以编写并逐步完善一个属于自己的 **Space**；内容变化后桌面端会重新加载。Space 尚未建好时，界面会展示 Library 文件，方便查看它已做的工作。

## 活动感知(可选授权)

授权后,Muse 能读取**本机活动记录**(你在用什么应用、切换了什么窗口),从而做出情境化的提醒——"你已经连续写了三小时代码了,歇会儿"。

关于这份数据,三件事说清楚:

1. 活动记录**只存在你的电脑上**,不上传;
2. 默认**不开启**,需要你显式授权;
3. 授权范围按 Agent 控制——默认只有 Muse,而且随时可以关。

## 日程

Muse(以及任何 Agent)可以维护自己的日程安排,到期自动执行或提醒。日程会汇入 [Amadeus 日历](../amadeus/calendar.md)以只读方式展示,一眼看到"AI 接下来要替你做什么"。

### 每周装备巡检

Muse 的日程里默认有一条**每周装备巡检**：它统计各个 Agent 最近 30 天在你自己的本机工作会话里用过哪些工具和技能（聊天模式、编程模式、团队讨论和云端会话的工具面不同，不计入），找出一直随每次请求携带、却从没用过的那些。只有数据足够（一个 Agent 至少 20 次运行）且确实有值得收起的内容时才会动手。每个 Agent 每次最多收起 8 个工具和 8 个技能，只从一次都没用过的里面挑；定义很小的工具收起来省不下什么，不会被收。其余的留到下一次巡检。

巡检完，Muse **直接替各个 Agent 把这几项收起**（见 [进化记录](overview.md#进化记录harnessmd) 的「装备」），不出建议卡片，也不需要你确认：收起只是把定义挪进按需目录，工具和技能照常可用，随时可以撤销。下次对话生效。那个 Agent 的「进化」页里会多出一条标着「Muse 代为收起」的装备条目，撤销或删除它就全部恢复；Muse 自己的日志里也会记一行这次替谁收了多少。在对话里直接让 Muse「现在巡检一次」，效果相同。

Muse 能代收的范围由程序重新核对，不由它自己说了算：只能是这次用量统计里列给那个 Agent 的工具和技能，别的名字会被拒绝；每个 Agent 每周最多一批（8 个工具 + 8 个技能）；某一项被那个 Agent 或你拿回来过，以后的巡检不再收它；在工具黑名单里关掉了 `manage_harness` 的 Agent 不会被代收。Muse 只能收起，不能给任何 Agent 增加能力，也不能替它写别的记录。不需要这项巡检时，在 Muse 的日程里删掉这一条即可，删除后不会再自动加回。

## 与自动化的关系

Muse 的盯任务适合口头一句话的轻量委托;需要精细编排(选 Agent、串多步动作、看执行历史)时,用[自动化](../spaces/automation.md)——两者底层同源,规则都在那里可视化管理。
