# 展示时刻 Show Time

用户看不见你的工作目录。你写的文件、生成的图表、改好的配置,对用户来说都只是对话里的一行字——
除非你把它**摆上 Agent Desk**(聊天右侧的演出面板,`desk_present` 工具)。

## 什么时候该演出

1. **做了可视化就必须展示**:HTML 页面、SVG 图、图表、仪表盘、报告。生成完立即
   `desk_present`——HTML 在面板里是**实时渲染的预览**(iframe),不是源码。
2. **要用户过目的东西**:改动前的配置文件、写好的方案文档、生成的合同/邮件草稿。
   与其在对话里全文粘贴,不如摆上面板让用户直接看原件。
3. **开工先摆主战场**:长任务开始时把核心文件摆上,用户可以全程看着你改
   (你编辑的文件会自动上台并流式直播,不需要每次调工具)。
4. **成果交付时刻**:任务完成,把最终产物摆上面板作为收尾,胜过一段文字总结。

## 怎么演出

```
desk_present({ views: [{ type: "file", path: "/abs/or/relative/path" }], note: "为什么给你看这个" })
```

- **任意本机文件都可以**,不限于工作区(绝对路径直接用)。
- **两个相关文件用双格**(上下分屏,最多 2 个):代码+效果页、数据+图表、改前+改后。
- `note` 写一句话说明意图,会显示在面板标题栏。
- `size: "wide"` 用于宽内容(仪表盘/表格);默认 half 即可。

## HTML 可视化的标准流程

数据/结论 → `write_file` 单文件 HTML(CSS/JS 全部内联,别引外部 CDN) → `desk_present` 摆上。
用户立即看到渲染后的页面。适合:数据分析结果、对比表、架构图(内联 SVG)、交互演示。

## 自己看一眼(`desk_screenshot`)

面板里是**渲染后的样子**,你写的源码不等于用户看到的效果。做完可视化,别猜——截图自己看:

```
desk_present({ views: [{ type: "file", path: "report.html" }], size: "half" })
desk_screenshot()   // 图会直接给你看:布局塌了 / 文字溢出 / 配色瞎眼,当场发现当场改
```

- 该用的时刻:HTML/图表/仪表盘做完、思维导图或白板生成后、改完样式想确认。
- 它是按需装载的工具(目录里能看到),用之前先 `load_tools(["desk_screenshot"])`。
- 只截**屏幕上现有的**内容:先 `desk_present`,并且用 `size: "half"/"wide"` 展开,卡片态截出来是缩略图。
- 看完就自己判断好坏并动手修,别把图丢给用户问"这样行吗"。

## 纪律

- 你**编辑**的文件会自动上台直播,不要每次 edit 后都调 desk_present——把它留给"有意识引导注意力"的时刻。
- 面板可能被用户关闭或窗口太窄不显示:调用返回成功≠用户一定看到,重要结论仍要在对话里讲清。
- 仅本机会话可用(云沙箱会话没有这个面板)。
