# 和 Obsidian 的手感对照(check:obsfeel)

## 这条检查是什么

同一份起始 Markdown + 同一串真按键,在 v4 统一编辑器(台架页 `harness.html?upage`,生产 `UnifiedPage` 全链)上重放,
把每个快照之后编辑器准备写盘的 Markdown(`serializeNow()`)和录好的 Obsidian 结果**逐字节**比,再按名单判红绿。
每一个「对齐 Obsidian」的改动都靠它验收:对齐了,名单上对应的条目从「待对齐」改成「相同」,之后再回退就红。

```bash
cd desktop
HARNESS_URL=http://localhost:<空闲端口>/harness.html npm run check:obsfeel            # 全套,几分钟
HARNESS_URL=… npm run check:obsfeel -- --only=K01,F                 # 只跑 K01 和 F 组
HARNESS_URL=… npm run check:obsfeel -- --only=K25 --update          # 按这次结果改名单
HARNESS_URL=… npm run check:obsfeel -- --dump=/tmp/obsfeel.json     # 顺手把 Forsion 一侧的结果存下来
```

`e2e-editor.cjs` 负责起停 Vite(端口上已经有人服务就复用,测的是那个进程的代码)。跑的时候别让别人写 `frontend/src`,
热更新会把页面重载;检查发现重载会把那个场景重跑一次。一遍大约 9 分钟(每个场景开一个新页面),
所以**不进 PR 的 CI**,先本地用;机器忙的时候慢一些,脚本里没有整体超时。

## 文件

| 文件 | 内容 |
|---|---|
| `scenarios.cjs` | 场景表:起始 Markdown + 步骤。计时类场景(P 开头)留在表里,这条检查不跑 |
| `baseline.json` | Obsidian 一侧的结果(基线) |
| `status.json` | 名单:每个比较项现在是哪种状态 |
| `../obsidian-feel.check.cjs` | 检查脚本(只依赖 `playwright-core` 和台架页) |

## 基线怎么来的

录自 Obsidian 1.15.1,实况预览,关掉全部核心插件、社区插件和拼写检查,其余缺省设置。同一张场景表、同一串按键,
在 Obsidian 里跑一遍,每个快照记编辑器里的全文(原样,不裁剪空白)。基线里只留能和 Forsion 直接比的东西:

- `snaps`:每个快照的全文。
- `traces`:逐键记录里「每按一次之后的全文」那种(K25、K26 的连按退格)。录的时候已经去掉了文末换行,检查对 Forsion 一侧做同样的裁剪。
  逐键的光标位置两边坐标系不同,不收。
- `clips`:复制 / 剪切事件交给剪贴板的数据。检查只比 `text/plain`(两边的 `text/html` 注定不同)。

驱动 Obsidian 的那一半不在本仓。Obsidian 升级、或者场景表加了场景,要在仓外重录基线再放进来。

## 比较项与名单

每个场景拆成若干比较项:`snap:<快照名>`、`trace:<步骤>`、`clip:<步骤>`,外加每个场景一条「重开稳定」(名单的 `reopen` 字段)。
每一项在名单里是三种状态之一:

| 状态 | 含义 | 什么时候红 |
|---|---|---|
| `same` 相同 | 和基线逐字节相同 | 现在不同了 → 回归 |
| `pending` 待对齐 | 还不同,打算对齐;拿不准归哪类的也先放这里 | 现在相同了 → 提示用 `--update` 改名单 |
| `keep` 刻意保留 | 不同,是 Forsion 有意的做法,带一句 `reason` | 现在相同了 → 同上 |

不同的项还记 `diff`:`eol` = 只差文末换行的个数,`content` = 内容不同。只差文末换行**不算相同**,单独记;
差异类型变了(`eol` ↔ `content`)也红,提示用 `--update` 确认。场景出错(锚点找不到、页面没起来)一律红。

**重开稳定**:每个场景跑完,把编辑器给出的 Markdown 当作一篇新笔记的内容打开,不做任何编辑再取一次,两次必须逐字节相同;
状态口径同上(`same` = 稳定)。注意:编辑器对没改过的块是逐字写回原文的,所以「不编辑直接重开」几乎总是稳定,
这一项抓的是逐字回填自己失效的情况,抓不到「解析再序列化」不幂等(那类问题见 `check:rtcorpus`)。

## 对齐了一条之后

1. 改编辑器,跑相关场景:`npm run check:obsfeel -- --only=<场景>`。对齐的那几项会红,提示「现在和基线相同了」。
2. 确认红的正是你要对齐的那几项(没有别的 `same` 变红),再跑 `--only=<场景> --update`,它会列出改了哪些条目。
3. 名单的改动和代码一起提交。合并前跑一次全套。

`--update` 只改这次跑到的场景;已有的「刻意保留」和理由会留着(变成相同的除外,它会改成 `same` 并列在改动里)。
要把一项改成「刻意保留」,手改 `status.json`:`"status": "keep"`,加一句 `reason`。

## 刻意保留的

理由写在 `status.json` 的 `reason` 里。现在有这几项:

- K15d 两个快照:`> 空格` 开的是折叠块(照 Notion 的做法,2026-11-14 定)。
- K26 的逐键记录:空待办一次退格整个清空。(同场景最后那个快照只差文末换行,记的是待对齐。)
- S04「撤销1」:敲 `# 空格` 立刻转成标题,撤销一次回到字面的 `# `。
- S12「撤销一次」:外部改动不进撤销记录。

同属保留、但这些场景里两边结果本来就相同的(R07 / R16 的 callout 直接编辑、R14 刚打完 `]]` 就是链接、C15 按词移动),记的是「相同」。
K17 的分割线:立刻转换是保留的做法,但存盘写 `***` 而不是敲的 `---` 是要对齐的,所以记待对齐。另有几条保留的做法(空列表项 / 空标题一次退格清空、「粘贴为纯文本」逐字插入、
标题和引用上 Tab 是视觉缩进、段落里的 `<br>` 不露原文、Chromium 原生的双击选词)目前没有对应的场景,不在名单里。

## 没覆盖的

- **没有真的写盘再重开**:比的是编辑器准备写盘的文本;「重开」走的是台架的内存文件,不经过主进程和磁盘。
- **输入法是模拟的**:CDP 的 `imeSetComposition` + `insertText`,不是真的系统输入法。
- 只比 Markdown:光标位置、选区、屏幕上露不露源码、弹层、截图都不比(这些要看人眼或别的检查)。
- 剪贴板只比 `text/plain`;粘贴步骤只看粘贴后的文档。
- 计时类场景(长文键入延迟)不跑。
- 无头 Chromium、mac 键位(`Mod` = ⌘)。
