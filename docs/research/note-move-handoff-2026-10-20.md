# 笔记移动期间漏字：交接正文与旧格式缓存

本轮接续 Windows Issue #70 / PR #120 的一次失败记录。此前同一代码的本机与 CI 复跑都通过，不能证明时序漏洞消失；这次先造出确定性失败才改产品代码。

## 两个已实测的根因

1. **v4 交接快照早于最后输入。** 真实 Electron 中暂停目标路径 `file:read-text` 的真实 handler，在旧编辑器里继续输入“末尾”：DOM 有“回来末尾”，磁盘只有“回来”。文件引用、路径和冲突副本检查都正常，只有后输入的字消失。`handOver` 退休旧管线后只取了一次全文，异步读取 / 写入期间与实例重建之前的输入不在那个快照里。
2. **v3 内存晚于实际编辑器。** 把库缩小到 100 篇填充，旧格式笔记移动后丢掉“续写”；随后输入也未落盘。Milkdown listener 在 200ms 防抖后才通知 store，销毁编辑器会取消该回调；移动交接与新页面 hydrate 在这之前读到了陈旧的块内容。

## 修复

- v4 为每个库 / pane / 目标路径登记一个有期限的交接读取器。目标实例在旧实例清理后读取它的最新正文，而非依赖 I/O 开始时的快照；以最后成功交接的旧正文为基线，把后续输入合入实际目标文件，保留已重写的附件引用及其他写者的修改。
- 旧实例始终禁止写旧路径；最后输入同步保存在目标路径的恢复草稿。目标实例以磁盘实际正文作为 CAS 基线，走现有单写者管线保存。无法合并时保留恢复副本，不能把旧引用或陈旧全文盲写回文件。
- 领取交接后旧实例的延迟清理不能重新生成草稿。读者按库 / pane 隔离，过期释放；光标续写只交回原活动 pane。
- v3 的块文档变化同步发布到 store；只对旧格式块启用，独立整篇编辑器与 v4 保存链保持原路径。序列化器与规范化规则沿用原 listener 的实现。
- GPT-6.1 Sol 复核抓到两条 P2，均已修：草稿更新超出配额时保留先前副本；已被目标编辑器继承的同一份草稿不再显示陈旧恢复提示。另覆盖复放 effect 时不重复领取交接。

## 留下的仪器

`desktop` 先构建，再运行 `npm run e2e:notemove:handoff`。它分两次真正启动 Electron，在目标读取中、写入已完成但 ACK 未返回时分别暂停真实 IPC，再继续输入。每次均检查 DOM 确实收到输入、完整磁盘正文、图片实际解码、零冲突副本 / 旧文件复活、无陈旧草稿或恢复条、无额外点击的光标续写，以及 v3 快速移动与接续保存。两阶段本机 **44/44** 通过；原有 1500 篇慢库压力脚本仍保留。该新仪器及相关单测已加入 Windows contracts CI，不依靠重复运行来把红灯刷绿。
