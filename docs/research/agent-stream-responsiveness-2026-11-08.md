# Agent 流式输出期间的界面响应（2026-11-08）

分两轮处理：先合并高频增量事件、复用稳定 Markdown，再处理切回长聊天时的同步布局。下方保留第一轮对照；后续布局改动和更严格的验收见文末。

## 改动

- 只在渲染层的 run 订阅出口合并兼容的 token、reasoning、tool_stream 和子 Agent 文本增量。首条立即交付，后续最多等待 40ms；非增量事件是同步顺序屏障。传输层仍按原始 seq 去重，工具身份或其他元数据不同的增量不会合并。
- 停止、完成、错误、断流和 watchdog 回灌前刷新缓冲；数据库快照覆盖前刷新，避免停止订阅时把已经持久化的尾部重复追加。
- 流式 Markdown 按解析器识别的顶层块和真实空行分组，保留末尾两组继续解析，稳定部分保留 React 树和 DOM。引用定义、脚注及非开头 BOM 回退到全文解析；完成时重新核对全文语法。
- 流式代码尾部暂缓语法高亮；标题锚点改用 AST 属性，避免每个增量创建新的标题组件类型。普通历史消息和第三方 README 保留全文解析路径。

## 可重复验证

环境：Windows 11 Pro 10.0.26200、Ryzen 5 5500、约 32GB 内存，Electron 40.10.2 / Chromium 144.0.7559.236；生产构建、临时用户目录、本地确定性 SSE 桩，未限速 CPU。基线为 `c103802490fe4bca4349fe1c8ba060b29cb493ff`，本轮涉及的生产文件与 `v2.13.8-beta.4` 相同。正式对比期间本任务没有并行构建或测试。

```sh
cd desktop
npm run build
node ../../.claude/hooks/devlock.cjs run --vehicle=e2e --what=agent-stream-performance --eta=5 -- node scripts/agent-stream-performance.check.cjs --json=/absolute/path/result.json
```

worktree 下需把 devlock 路径改为仓根的绝对路径。基线构建加 `--baseline`，只跳过延迟预算，仍检查完整性。`--profile` 额外输出切页阶段的 Chromium CPU profile；剖析数据不能冒充无剖析开销的正式对比。

负载：先展示 24,268 字符的 Markdown，包含 35 组标题、公式、代码块和表格，再每 20ms 排入一段文本，共 1,600 段。输入 62 个字符，每键间隔 35ms。第二轮输出 1,000 段，用真实 ribbon 点击完成 Tangu ↔ Amadeus 三次往返。

输入延迟从自动化发送请求前计时到输入后的下一次绘制，包含 IPC 与队列开销；不是原生硬件按键延迟。切页延迟包含真实点击、目标激活、草稿核对与下一次绘制。单机各一轮正式对比、六次切页，不能视作多设备性能承诺。

## 剩余瓶颈

单独的切页 CPU profile 显示，三次返回聊天时约 7.2 秒在 `flushSync` 路径，其中约 5.7 秒处于提交阶段：`UserFold` 首次 `offsetHeight` 测量约 3.0 秒，`ChatView` 吸底初始化中的布局读取约 2.5 秒。这是同步读取触发浏览器布局的归属，不等于这两个函数的纯 JavaScript 计算耗时。profile 含采样开销，不能直接替代上表的无剖析结果。

后续应单独处理长聊天重新挂载时的布局测量和滚动初始化。本轮没有改动全局 Space 过渡或折叠、滚动行为。超长单块、全文引用回退、多 Agent 并发、中文输入法组合输入和真实工具 CPU 争用未作性能验收；确定性 SSE 只验证界面事件消费，不验证模型行为。

## 后续：切回长聊天的布局

用户进一步要求切页延迟低于 700ms。保留同机、生产构建、窗口和 SSE 负载，增加以下改动：

- 长提问折叠和输入框响应布局使用 ResizeObserver 已计算的尺寸；右侧任务卡片的渲染后测量合并到下一帧，避免在父聊天定位前触发全页布局。搜索命中可在首次尺寸送达前展开长提问。
- 对长回答中的段落、表格和带标题栏代码块启用块级 `content-visibility`。引用、列表、块公式保持原布局，避免改变外边距合并；工具切分的多个正文段仅最后一段保留 16 个增长块的真实高度。
- 移除聊天挂载时的重复吸底测量。滚动跟随改由明确的滚轮、触摸、键盘、滚动条拖动和目录跳转意图控制，浏览器的高度修正不再改变跟随状态。`scrollToElement` 在根容器发出导航事件，保持 TOC、搜索和画布跳转的共用路径。
- 流式淡入动画复用文本节点索引；正文 DOM 改动、代码高亮或嵌入替换子节点时失效，避免每个动画帧都遍历整条长回复。
- Markdown 分块和渲染共用固定语法的原始 AST 缓存（源文本总长 ≤256KiB、≤512 条）；返回独立副本，标题编号、双链、软换行等上下文变换仍逐次执行。单公式 KaTeX 输出缓存限制为 ≤20,000 节点、≤128 条，只缓存无诊断的成功结果，保留原插件的信任策略和错误祖先路径。后续 MathBox 等变换拿独立副本；URL 安全与 React 输出仍由 react-markdown 负责。

探针的切页终点收紧为：实际最后一个字符所在行完整位于输入框上方，再等下一次绘制；报告单列切回聊天的三次样本。测量后继续验证向上阅读不被拉回、点击按钮和向下滚动恢复跟随、完成后仍在底部，以及正文编号和草稿完整性。失败报告保留最近的滚动位置记录。

新增 `check:chatlayoutblocks` 用真实 Electron 检查折叠/展开/收起、长回复内部 TOC 落点、代码复制，并把段落、引用、列表、公式、表格、代码的实际几何与关闭块隔离后的参考结果比较（差异 ≤1px）。另用 18 次工具调用交错 19 段正文，核对稳定段使用隔离而只有一个增长尾部。

聚焦评审提出滚动意图竞态、工具分段尾部豁免过宽，以及输入框遮挡下的验收假阳性；均纳入本轮修正和 GUI 验证。原仅用 `scrollTop` 赋值模拟用户上滚的旧检查改用真实滚轮，目录的程序跳转仍由实际 TOC 点击覆盖。

仅布局与 DOM 索引优化的两次严格复测中，首轮三次返回为 692 / 670 / 672ms，但下一轮首返仍为 764ms，因此没有采用这组“偶尔达标”的结果交付。随后补充上述解析/公式缓存。对新增缓存的单独聚焦评审指出错误诊断祖先路径及结束后 240ms 淡入期间的 DOM 失效问题；修正并增加针对断言，未对旧问题反复评审。

### 最终结果

同一最终构建独立运行两轮，期间不并行构建或其他测试。环境、负载和测量开销同前，切页就绪判据比第一轮更严格。

| 指标 | 第一轮优化后 | 最终复测 A | 最终复测 B |
| --- | ---: | ---: | ---: |
| 三次切回长聊天 | 2,239 / 2,199 / 2,148ms | 633 / 552 / 553ms | 669 / 545 / 557ms |
| 切回长聊天 P95 / 最大值 | 2,239ms | 633ms | 669ms |
| 运行期间打字 P95 | 72ms | 65ms | 82ms |
| 运行期间打字最大值 | 752ms | 191ms | 167ms |
| 运行期间完成的字符 | 62 / 62 | 62 / 62 | 62 / 62 |
| 整段输入时间（含逐键间隔） | 5,257ms | 3,884ms | 4,221ms |
| 正文/草稿完整性 | 通过 | 通过 | 通过 |
| 700ms 切页预算 | 未通过 | 通过 | 通过 |

最终六次返回全部 <700ms，最慢值相对第一轮下降约 70%。两轮均核对 1,600 + 1,000 个输出编号完整、唯一、有序，草稿逐字一致，最后一行处于输入框上方；向上阅读、按钮恢复跟随、向下滚动恢复跟随及终态位置都通过。无未捕获渲染错误，最终真实截图已查看。[两轮逐键及切页数据](assets/agent-stream-2026-11-08/layout-comparison.json)保留独立样本；完整 JSON、截图与中间失败记录在本机 `perf/`。

本轮相关单测共 65 项：原流式 Markdown 23、卡片收缩 16、既有文件链接/嵌入/公式复制 11、新折叠 2、淡入 DOM 缓存 1、解析和 KaTeX 等价性 12。类型检查、生产构建、Tangu 边界检查（43 个负对照）通过；真实 Electron 的块排版/工具交错 7 项、滚动目录 6 项、窄输入框 43 项通过。

这是该机器和上述负载下的验收，未覆盖中文输入法组合输入、其他设备、多个真实工具争抢 CPU、超长单块和大量引用定义回退。确定性 SSE 验证界面消费事件的流畅度，不代表真实模型或工具行为。改动尚需经 PR 合并和发布才能进入安装版。
