# 记忆系统

Forsion 的 Agent 可以跨会话保留你的工作偏好、事实与项目背景。你可以明确要求它记住内容，也可以启用后台整理来收集和维护记忆。下一次对话时，这些背景可以继续参与工作。

## 记忆长什么样

默认按 Agent 管理记忆，文件夹里有可编辑的 `MEMORY.md`，并保留版本与来源记录。部分 Agent 可以明确配置为共享默认 Agent 的记忆，面板会显示提示。

- **查看与修订**：打开当前 Agent 的记忆面板，检查它记下的事实，添加或修改内容；
- **追溯**：查看记忆版本及来源，按需恢复；
- **遗忘**：将事实移出活跃记忆，并阻止旧同步把它重新带回。版本历史仍保留原文供审计，遗忘不等于物理擦除。

也可以直接编辑本地 `MEMORY.md`；面板提供了集中查看和管理的入口。

## 两级：Agent 记忆与项目记忆

你告诉 Agent 的、纠正它的、要求它的，都进记忆。记到哪一级取决于这件事在哪里成立：

| | Agent 记忆 | 项目记忆 |
|---|---|---|
| 记什么 | 换个项目也成立的：你是谁、你的偏好、你要求它一贯怎么做 | 只在这个项目里成立的：命令、目录、约定、你针对这个项目提的要求 |
| 谁看得到 | 这个 Agent，在哪里工作都带着 | 在这个项目里工作的所有 Agent；别的项目和不属于任何项目的会话看不到 |
| 在哪里看 | Agent 详情 → 成长 → 记忆 | 项目详情 → 配置 → 项目记忆（可逐条删除） |
| 存在哪 | Agent 文件夹里的 `MEMORY.md` | 本机用户目录下按项目路径索引，不写进项目文件夹，不随云端同步 |

在项目会话里，Agent 记一件事时必须选一级；后台复盘（Historian）收集候选时也分两组：换个项目也成立的进 Agent 的候选、经 Dream 整理后进入记忆，只在这个项目成立的直接写进项目记忆（同一段对话里 Agent 自己已经记过项目记忆时，后台不再补记；带网址或提到凭据、审批、权限的内容后台不写）。项目记忆上限 8,000 字，写满后不会自动挤掉旧条目。后台记的条目被你删掉后，同一段对话里后台不会再把它写回来；别的对话里换了说法的同一件事识别不出来。

项目记忆按项目文件夹的路径认项目：文件夹挪了位置，原来那份就对不上了。对话时回忆起的历史片段如果来自另一个项目，会标明出处，Agent 不会把它当成当前项目的事实。

## 从经历到可用的记忆

你可以在对话里明确要求 Agent 记住一项偏好或事实。启用 **Historian** 后，它还会整理会话日志并收集记忆候选。

**Dream（梦境整理）**对这个 Agent 的已有记忆与待审核候选进行归并。可以手动发起，也可以配置自动维护；自动整理默认开启，可按 Agent 关闭。整理时会检查候选的来源，避免把缺乏依据的内容写成长期事实。

对话时的**回忆**会在 Agent 的范围内查找相关记忆与历史会话片段。知识库仍负责保存完整的项目材料，记忆负责保留有持续价值的背景。

## 记忆 vs 资料库

| | 记忆(MEMORY) | 资料库(Library) |
|---|---|---|
| 谁来写 | Agent 在相处中自动记 | 你主动放进去 |
| 内容 | 关于你的偏好与事实 | 参考资料、文档、规范 |
| 典型例子 | "用户喜欢简洁的回答" | 一份产品需求文档 |

## 三端看到的是同一份记忆

登录 Forsion 账号后:

- 一轮对话结束,这个 Agent 的记忆与日志立刻上云;
- 打开记忆视图时自动拉取云端最新;
- 桌面、[浏览器版与移动端](../reference/web-and-mobile.md)因此看到的是同一份记忆,不用等下一次同步。

没登录账号时,记忆只待在本机的 Agent 文件夹里。

## 云端会话的 Historian

在浏览器版与手机上进行的云端会话,空闲下来后由 **Historian** 自动收尾:总结会话标题、记录当天的日志。这项能力需要管理员在后台开启;没开启就不会有人替你整理,会话与日志都保持原样。

## 会话摘要不是记忆

这是两件事,别混:

- **会话摘要**是单条会话的内容概要——侧栏悬停即可预览,在笔记里用 `[[` 也能引用某条会话;
- **记忆**是跨会话累积的、关于你的事实,每次对话都会带上,直接影响 Agent 怎么回答你。

换一条会话,摘要就换一份;记忆则一直跟着这个 Agent。
